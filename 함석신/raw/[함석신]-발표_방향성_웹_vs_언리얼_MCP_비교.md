# 🎤 발표 방향성 및 비교 전략 가이드: 웹 개발 vs 언리얼 + MCP

> **문서 버전:** v1.0  
> **작성자:** 함석신 (기획 파트)  
> **목적:** 내일 발표를 위한 [웹 개발 파트]와 [언리얼 + MCP 파트]의 기술 실증 비교 분석 및 슬라이드 구성 방향성 정립

---

## 1. 발표 개요 및 기획 의도 (Executive Summary)

* **발표 핵심 메시지**:  
  "단순한 결과물 자랑이 아닌, **'동일한 목적(AI 기반 개발/프로토타이핑) 아래 서로 다른 두 기술 스택(웹 vs 게임엔진)이 보여준 AI 활용 방식과 실무 파이프라인의 실증적 차이'**를 기획적·비즈니스적 관점에서 입체적으로 전달한다."
* **기획자의 포지셔닝**:  
  두 파트의 우열을 가리는 것이 아니라, 각 기술 스택이 가진 **Time to Market(시장 출시 속도)**과 **Fidelity(완성도/몰입도)** 간의 트레이드오프를 명확히 제시하여 조직 차원의 실무 인사이트를 도출.

---

## 2. ⚖️ 슬라이드 핵심 비교 포인트 3가지 (Core Narrative)

### 포인트 1. 개발 속도 및 진입장벽 (Time to Market & Prototyping)
* **웹 개발 파트 (Fast Prototyping)**:
  * **특징**: FastAPI, React/Vanilla 웹 기술을 활용해 몇 시간 만에 핵심 비즈니스 로직과 UI/UX를 뚝딱 구현.
  * **장점**: 개발 환경 세팅이 가볍고 배포/공유가 즉각적이며, 아이디어 검증(Lean Validation) 주기가 극단적으로 짧음.
* **언리얼 + MCP 파트 (Core Experience & High Fidelity)**:
  * **특징**: 엔진 프로젝트 구성, 3D 공간/에셋 로딩, 물리 법칙(Physics), 렌더링 파이프라인 등 초기 진입장벽이 높음.
  * **장점**: 높은 진입 비용을 감수한 만큼, 웹에서는 불가능한 '실제 조작 가능한 게임다운 형태'와 깊이 있는 시뮬레이션 환경 구축에 집중.

---

### 포인트 2. 기술 스택과 AI의 역할 차이 (AI Utility & Next-gen Workflow)
* **웹 개발 파트 (AI as a Co-pilot / Feature Partner)**:
  * **AI의 역할**: 데이터 전처리/분석, 코드 생성 보조, 서비스 로직 내 API 호출을 통한 기능 결합.
  * **특징**: 가볍고 유연하게 AI가 보조자(Co-pilot) 또는 서비스의 기능 컴포넌트로 밀결합됨.
* **언리얼 파트 (MCP 기반 Next-gen Agentic Pipeline)**:
  * **AI의 역할**: 단순 코드 어시스턴트를 넘어, **MCP(Model Context Protocol)**를 통해 IDE의 AI 에이전트가 언리얼 에디터 내부의 액터(Actor), 컴포넌트, 엔진 런타임 상태를 직접 조작.
  * **특징**: 개발자가 툴을 다루는 방식 자체를 혁신하는 차세대 워크플로우(AI Agentic Workflow)를 실제 엔진 환경에서 실험·실증.

---

### 포인트 3. 실무 파이프라인(인력·기간·비용)의 실증적 비교 (Business Decision)
* **실무 결론 도출**:
  > *"만약 가벼운 서비스나 빠른 비즈니스 검증이 필요하다면 **웹 + AI 조합**이 압도적으로 효율적이지만, 깊이 있는 물리 시뮬레이션과 몰입감이 필요한 코어 콘텐츠라면 **엔진과 최신 프로토콜(MCP) 기반의 전문 파이프라인**이 필수적이다."*
* **ROI 관점의 접근**:
  * **웹 파트**: 최소 인력(1인 개발 가능), 수 시간~수 일 단위의 최소 비용 검증.
  * **언리얼 파트**: 엔진/C++ 전문 지식 요구, 고비용이지만 장기적 프로덕트 자산화 및 높은 유저 몰입도 확보 가능.

## 3. 📊 [발표 슬라이드용] 웹 vs 언리얼 개발 파이프라인 비교 매트릭스

발표 자료 한 장으로 두 파트의 차이를 명확히 정리할 수 있는 핵심 비교표입니다.

| 비교 항목 | 🌐 웹 개발 파트 (FastAPI / Web) | 🎮 언리얼 + MCP 파트 (Unreal Engine 5) |
| :--- | :--- | :--- |
| **핵심 목표** | 초고속 프로토타이핑 & 기능 검증 | 게임성 구현 & 코어 물리/공간 시뮬레이션 |
| **주요 기술 스택** | Python (FastAPI), HTML/JS/CSS | Unreal Engine 5, C++, Blueprint |
| **AI 활용 형태** | **Co-pilot / Feature Integration**<br>(코드 생성 보조, 데이터 처리, API 연동) | **Next-Gen Workflow (MCP)**<br>(AI 에이전트가 언리얼 에디터/오브젝트 직접 제어) |
| **개발 소요 시간 (TTM)** | 수 시간 ~ 1~2일 내 즉시 가동 | 초기 환경/에디터 파이프라인 구축에 집중 투자 |
| **진입장벽 및 학습곡선** | 낮음 (웹/스크립트 기본 지식으로 구현 가능) | 높음 (엔진 구조, C++, MCP 브리지 이해 필요) |
| **몰입감 & 물리 환경** | 브라우저 기반 2D/간이 인터랙션 | 실시간 물리 엔진, 3D 공간감, 고품질 렌더링 |
| **최적의 비즈니스 단계** | MVP 가설 검증, 초기 기획 아이데이션 단계 | 상용 게임/인터랙티브 콘텐츠 코어 개발 단계 |

## 4. 📋 기획자 D-1 실전 액션 플랜 (Action Plan)

### STEP 1. 웹 파트 팀원과 5분 퀵 싱크 (수치 데이터 수집)
웹 파트 팀원에게 아래 질문을 통해 **발표에 넣을 구체적인 '실제 수치'**를 확보합니다.
* **Q1. 사용한 주요 기술 툴**: (예: FastAPI, Streamlit, Claude/Cursor 등)
* **Q2. 핵심 기능 구현까지 걸린 순수 개발 시간**: (예: 기획부터 동작까지 약 00시간 소요)
* **Q3. AI 활용으로 가장 크게 체감한 단축 포인트**: (예: API 라우팅 생성, UI 레이아웃 등)
* **Q4. 진행 중 느낀 한계나 아쉬운 점**: (예: 복잡한 3D 인터랙션 표현 한계 등)

### STEP 2. 슬라이드 2장 구성 전략
* **슬라이드 A (스토리 전개)**:  
  * 좌측(웹): "빠른 검증을 위한 Web+AI 초고속 프로토타이핑" (실제 화면 캡처)  
  * 우측(언리얼): "깊이 있는 콘텐츠를 위한 UE5 + MCP 에이전트 제어 실험" (에디터 조작 화면)
* **슬라이드 B (종합 비교 & 결론)**:  
  * 위 섹션 3의 **[비교 매트릭스 표]**를 단독 슬라이드로 배치.
  * 하단에 기획자 한 줄 제언(Key Takeaway) 강조:  
    *"상황과 목적에 맞는 최적의 AI 개발 파이프라인 선택 전략"*

### STEP 3. 발표 멘트 (스크립트 키포인트)
> "저희 팀은 이번 프로젝트에서 단순히 한 가지 결과물을 내는 것을 넘어, **웹 기술과 게임 엔진이라는 서로 다른 두 환경에서 AI가 어떻게 작동하고 개발 생산성을 바꾸는지**를 비교 검증했습니다.  
> 웹 파트가 몇 시간 만에 아이디어를 시장에 내놓는 '속도'의 가능성을 보여주었다면, 언리얼 파트는 MCP를 통해 AI가 에디터와 오브젝트를 직접 핸들링하는 '차세대 워크플로우'의 비전을 실증했습니다."
