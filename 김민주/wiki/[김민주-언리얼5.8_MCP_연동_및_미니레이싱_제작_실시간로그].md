## 📌 1. 핵심 개념 및 요약 (Key Takeaways)

* **핵심 명제**: 언리얼 엔진 5.8의 공식 Model Context Protocol(MCP)을 IDE의 AI 에이전트와 결합하면 고난도 3D 게임 제작 파이프라인의 에셋 배치와 레벨 구성을 획기적으로 단축할 수 있으나, 네트워크 소켓 설정, 엔진 내부 플러그인 의존성 해결, 미세 조작감 물리 튜닝은 여전히 숙련된 인간 개발자의 개입이 필수적이다.
* **3줄 요약**:
  1. **초기 설정 장벽 극복**: 언리얼 5.8 MCP 서버는 기본값이 꺼져(`bAutoStartServer=false`) 있고 포트(8000)와 Streamable HTTP 규격을 맞추어야 하므로 AI가 엔진 코드를 직접 역분석하여 `ini` 및 `mcp_config.json`을 자동 복구함.
  2. **2일 단기 대결 체계**: 비개발자의 순수 웹 바이브 코딩(김준호)에 맞서, 시니어 기획(함석신)의 연출 가이드와 언리얼/VFX 전문성(김민주)을 갖춘 팀이 AI와 페어로 3D 카트라이더를 제작.
  3. **전수 기록 원칙**: 연동 오류 진단부터 에셋 배치, 충돌 물리 튜닝까지 모든 과정을 분 단위로 전수 기록하여 'AI의 실질적 개발 인정 바운더리'의 객관적 증거로 삼음.

## ⚖️ 3. 개발 환경 속 AI 인정 바운더리 검토 (Boundaries & Risks)

### 3.1 도구로서의 인정 수준 (Tool vs Creator)
* **네트워크 및 환경 구성**: 언리얼 엔진의 C++ 소스 코드를 읽고 숨겨진 콘솔 명령어(`ModelContextProtocol.StartServer`)와 INI 설정 키값을 찾아내는 것은 AI의 뛰어난 역량이 증명된 영역입니다.
* **창작 의도의 부재**: 하지만 "돌담길 머티리얼을 깔고 급커브 헤어핀을 만들어 플레이어에게 충돌 긴장감을 주자"는 식의 **게임성(Playability)과 감성적 기획은 철저히 5~6년차 현업 기획자(함석신)의 인간적 통찰**에서 비롯되었습니다.

### 3.2 이해관계자 관점 비교 (실무 제작진 vs 생성형 AI)
| 구분 | 내용 (언리얼 파트) | 비고 |
| :--- | :--- | :--- |
| **인간 기획자/개발자 (함석신, 김민주)** | 전체 게임의 연출 톤, 유저가 느낄 헤어핀 코너의 손맛, 에디터 파이프라인 무결성 수호 | 본질적인 재미 및 최종 검증 담당 |
| **AI 에이전트 (Antigravity IDE)** | 번거로운 엔진 환경 설정 분석, 에셋 배치 반복 작업 실행, MCP JSON 통신 디버깅 | 반복 노동 제거 및 파이프라인 윤활유 |
