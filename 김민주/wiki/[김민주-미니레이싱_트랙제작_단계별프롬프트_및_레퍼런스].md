## 📌 1. 핵심 요약 (Key Takeaways)

* **핵심 명제**: 게임 엔진 제어형 AI(MCP)에게 단일의 모호한 프롬프트로 "맵을 만들어줘"라고 요청하면 실패하지만, 개발 파이프라인 순서(환경 설정 ➔ 바닥 ➔ 트랙 스플라인 ➔ 스폰 ➔ 건물 ➔ 식생)에 따라 **제약 조건(Constraint)이 명시된 6단계 모듈식 프롬프트**를 주입하면 실시간 주행 가능한 고품질 맵을 자동 생성할 수 있다.
* **3줄 요약**:
  1. **사전 제약 조건 명세**: 80m x 80m 폐곡선 스플라인, 도로 중심선 7m 안전 영역, UpVector(0,0,1) 고정 등 물리적 규칙을 프롬프트에 선제 반영.
  2. **단계적 자산 스캔과 바인딩**: 0단계에서 에셋 라이브러리를 먼저 질의(Query)하여 실제 존재하는 정적 메시 경로를 확인한 후 배치에 활용하는 2-Phase 전략 채택.
  3. **인간 디렉터의 동선 설계**: 조감도 기반의 출발-헤어핀-외곽 직선-로터리 루프로 이어지는 핵심 레이싱 재미는 인간 기획자가 정의하고, AI는 배치 연산 실행자로 기능.

## 🔍 2. 게임 개발 현장 분석 및 데이터 (Detailed Analysis)

### 2.1 6단계 프롬프트 파이프라인 구조도

```mermaid
flowchart LR
    P0["0단계: 에셋 스캔<br>& 모드 검증"] --> P1["1단계: 지반 구축<br>(100x100m Base)"]
    P1 --> P2["2단계: 스플라인 트랙<br>(80x80m Closed Loop)"]
    P2 --> P3["3단계: 스타트 세팅<br>(PlayerStart & 게이트)"]
    P3 --> P4["4단계: 건물/랜드마크<br>(안전거리 7m 준수)"]
    P4 --> P5["5단계: 자연 식생/소품<br>(랜덤 회전/스케일)"]
```

### 2.2 단계별 프롬프트 제어 파라미터 및 API 분석

| 단계 | 프롬프트 핵심 목표 | 제어 파라미터 및 API | 비고 |
| :--- | :--- | :--- | :--- |
| **0단계: 사전 검증** | 에셋 가용성 확인 및 차량 모드 바인딩 | `WorldSettings.game_mode_override_class`, `EditorAssetSubsystem` | 존재하지 않는 에셋 참조 버그 원천 차단 |
| **1단계: 바닥 베이스** | 100m x 100m 평면 스폰 및 추락 방지 충돌체 설정 | `Scale(100, 100, 1)`, `CollisionProfileName='BlockAll'` | 타이어 관통 방지 |
| **2단계: 트랙 스플라인** | 3~4회 연속 헤어핀 및 로터리 포함 폐곡선 도로 생성 | `SplineComponent(bClosedLoop=True)`, `SplineMeshComponent` | `UpVector=(0,0,1)`로 도로 꼬임 방지 |
| **3단계: 스타트 지점** | 차량 스폰 위치 및 결승선 트리거 세팅 | `PlayerStart`, 접선 방향 일치 `Yaw`, `BoxTriggerComponent` | 주행 시작 시 전방 조준 보장 |
| **4단계: 건축물 배치** | 마을 가옥 12채 및 풍차/타워 랜드마크 배치 | `Centerline Distance >= 7.0m`, 아웃라이너 `Environment_Buildings` | 주행선 시야 확보 및 경로 침범 차단 |
| **5단계: 소품 & 식생** | 침엽수, 활엽수, 나무통 40~50개 무작위 분산 | `Random Yaw(0~360°)`, `Scale(0.8~1.2)`, 반경 5m 회피 | 자연스러운 환경 밀도 형성 |

## ⚖️ 3. 개발 환경 속 AI 인정 바운더리 (인정 한계선 검토)

### 3.1 도구로서의 인정 수준 (Procedural Execution Tool)
* **인정 범위**: 텍스트 명령어를 바탕으로 수백 개 오브젝트의 월드 좌표를 계산하고, 언리얼 엔진의 복잡한 Python/C++ API를 호출하여 아웃라이너 계층 구조를 정리하는 **'실행 자동화 툴'로서의 가치는 100% 인정**.
* **한계선**: AI는 "어떤 곡률이어야 카트라이더 특유의 드리프트 쾌감이 극대화되는가?"를 판단하지 못함. 80m x 80m 사각 영역 내 헤어핀의 위치, 다리 통과 시점, 결승선 게이트의 배치와 같은 **플레이 감각(Game Feel)은 인간 기획자의 조감도 분석과 수학적 좌표 설계가 필수적으로 개입**해야 함.

### 3.2 개발 영역별 영향 및 시사점
| 개발 영역 | AI 도입에 따른 변화 | 인간 개발자의 고유 영역 |
| :--- | :--- | :--- |
| **레벨 디자인 (Level Design)** | 에셋 배치 반복 노가다(드래그&드롭) 90% 이상 절감 | 코너 반경, 점프 각도, 속도감 연출 등 핵심 게임 메커닉 설계 |
| **기술 아트 (Tech Art)** | 에셋 경로 질의, 머티리얼 바인딩, 충돌체 자동 셋업 | 셰이더 최적화, 드로우콜 관리, 조명 무드 튜닝 |
| **기획 (Game Design)** | 텍스트 프롬프트를 통한 프로토타입 즉시 시각화 | 난이도 곡선, 사용자 리텐션 요소, 차별화 테마 수립 |
