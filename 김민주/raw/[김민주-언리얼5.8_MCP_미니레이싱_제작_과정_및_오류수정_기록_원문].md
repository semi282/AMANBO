## 2. 기술 인프라 및 MCP 통신 아키텍처

### 2.1 언리얼 5.8 ModelContextProtocol 구조
* **서버 엔드포인트**: `http://127.0.0.1:8000/mcp`
* **통신 규격**: JSON-RPC 2.0 (Streamable HTTP 2025 규격 준수)
* **핸드셰이크 헤더**: 
  * `Mcp-Session-Id`: 언리얼 엔진 리스너가 발급하는 고유 세션 키 (예: `b9e147834c75e400b7f6dfa4aea8edae`)
  * `Content-Type: application/json`
* **통신 브리지 클라이언트 (`ue_mcp.py`)**:
  * 언리얼 엔진 내장 파이썬 3.11 인터프리터(`UE_5.8/Engine/Binaries/ThirdParty/Python3/Win64/python.exe`)를 활용.
  * IDE 백그라운드 셸과 언리얼 에디터 간의 양방향 RPC 브리지 클래스 `UnrealMCPClient`를 자체 구축하여 52개 툴셋을 자유롭게 호출.

### 2.2 주요 호출 MCP 도구 목록
1. `editor_toolset.toolsets.scene.SceneTools.add_to_scene_from_asset`: 에셋 경로를 기반으로 정적 메시/블루프린트 스폰
2. `editor_toolset.toolsets.scene.SceneTools.remove_from_scene`: 액터 제거
3. `editor_toolset.toolsets.actor.ActorTools.set_label` / `set_actor_folder`: 아웃라이너 계층 구조 정리
4. `editor_toolset.toolsets.actor.ActorTools.add_component`: 액터 내 서브 컴포넌트 동적 주입 (`SplineComponent`, `SplineMeshComponent`)
5. `editor_toolset.toolsets.object.ObjectTools.set_properties`: 컴포넌트 세부 프로퍼티 JSON 오버라이드
6. `EditorToolset.EditorAppToolset.StartPIE`: 에디터 내 실시간 플레이 세션 구동
7. `EditorToolset.EditorAppToolset.SetCameraTransform`: 뷰포트 카메라 좌표/각도 제어

## 5. 발생 오류 진단, 원인 분석 및 해결 과정 (전수 기록)

스프린트 진행 중 발생한 기술적 오류와 해결 과정은 다음과 같습니다.

### [오류 1] 엔진 재기동 직후 MCP 세션 단절 및 404/Unknown Method 오류
* **발생 시각**: 09:23:49 ~ 09:28:15
* **현상**:
  * Fab 에셋 642개를 임포트하면서 언리얼 에디터가 재기동됨.
  * Antigravity IDE가 이전 세션 ID로 통신을 시도하거나 `server/discover` 엔드포인트를 호출할 때 `Call to unknown method "server/discover"` 반환 및 소켓 단절 발생.
* **원인 분석**:
  * 언리얼 엔진 5.8의 ModelContextProtocol 플러그인은 상태 비저장(Stateless) HTTP 포트 8000 리스너로 동작하며, 엔진 재기동 시 내부 세션 테이블이 초기화됨.
  * 또한 언리얼 MCP는 표준 프로토콜 외의 임의 탐색 메서드(`server/discover`)를 지원하지 않음.
* **해결 조치**:
  1. 표준 MCP `initialize` JSON-RPC 규격(protocolVersion `2024-11-05`)으로 재접속 핸드셰이크 전송.
  2. 에디터 리스너로부터 새 `Mcp-Session-Id`(`b9e147834c75e400b7f6dfa4aea8edae`)를 정상 수신하여 모든 요청 헤더에 주입.

### [오류 5] 개별 정적 메시 배치에 따른 도로 이음새 파편화 및 틈새(Gap/Cracking) 버그
* **발생 시각**: 10:22:39 ~ 10:25:20 (가장 치명적인 엔진 물리 버그)
* **현상**:
  * 뷰포트 및 실제 주행 시, 커브 구간에서 직선형 도로 메시(`SM_Track_10M`)들이 매끄럽게 연결되지 못하고 각진 형태로 꺾이면서 메시와 메시 사이에 눈에 띄는 V자형 틈새(Gap)와 단차가 발생함.
  * 차량이 코너를 돌 때 이 틈새에 바퀴 충돌체가 걸려 차량이 튀어 오르거나 전복되는 물리 오류 발생.
* **원인 분석**:
  * 정적 메시(Static Mesh)는 변형되지 않는 강체(Rigid Body)이므로, 곡률 반경이 작은 급커브 구간에서 직선형 박스 메시를 촘촘히 잇더라도 기하학적으로 외곽 틈새 발생이 불가피함.
* **해결 조치 (SplineMeshComponent 전면 전환)**:
  1. 기존의 파편화된 도로 조각 액터 49개 전량 삭제(`remove_from_scene`).
  2. 단일 액터 `Continuous_Spline_Track` 생성 후 `SplineComponent(bClosedLoop = True)` 장착.
  3. 28개의 닫힌 루프 제어점 좌표를 바닥 높이 `Z=5.0`으로 평탄화 고정.
  4. 인접 점들 사이의 접선 벡터를 3차 에르미트 보간(Hermite Spline Tangent) 공식으로 연산:
     ```python
     # 부드러운 C1 연속 접선 연산
     t1_dir = normalize((p2[0] - p_prev[0], p2[1] - p_prev[1]))
     t2_dir = normalize((p_next[0] - p1[0], p_next[1] - p1[1]))
     t1 = (t1_dir[0] * dist, t1_dir[1] * dist)
     t2 = (t2_dir[0] * dist, t2_dir[1] * dist)
     ```
  5. 28개 세그먼트마다 `SplineMeshComponent`를 동적으로 생성하여 시작점/끝점의 위치, 접선, 회전을 정밀 바인딩:
     * `Start Roll = 0.0`, `End Roll = 0.0`, `SplineUpDir = (0, 0, 1)`로 고정하여 도로 뒤틀림(Twist) 현상 원천 차단.
     * `BodyInstance`: `CollisionProfileName = 'BlockAll'`, `CollisionEnabled = 'QueryAndPhysics'`.
  6. **결과**: 메시 자체가 스플라인 곡률을 따라 물리적으로 휘어지며(Deformation) 연결되어, 단 1mm의 틈새도 없는 완전 무결한 일체형 폐곡선 아스팔트 트랙 완성.

### [오류 7] 에디터 버퍼와 디스크 파일 간의 충돌 (Dirty Write Prevention)
* **발생 시각**: 09:17 및 10:20경
* **현상**:
  * 사용자가 IDE 에디터 탭에 `mcp_config.json`이나 마크다운 파일을 열어둔 상태에서 AI가 디스크에 직접 파일을 수정했을 때, 사용자가 저장을 누르면 `Failed to save: The content of the file is newer` 경고 발생.
* **원인 분석**:
  * VS Code 기반 IDE의 안전장치로, 메모리 버퍼 내용과 디스크 내용의 타임스탬프 불일치 시 덮어쓰기를 방지함.
* **해결 조치**:
  * 사용자에게 해당 탭을 '저장 안 함(Don't Save)'으로 닫고 다시 열거나 'Overwrite'를 누르도록 명확한 행동 지침을 제공하여 데이터 유실 없이 동기화 완료.

## 6. 결론 및 실증 교훈 (Lessons Learned)

1. **소요 시간 단축 효과 (14분 vs 수 시간)**:
   * 수작업으로 에셋을 하나씩 드래그 앤 드롭하고 좌표를 맞추는 레벨 디자인 방식 대비, MCP와 파이썬 수학 보간 스크립트를 결합한 자동화 파이프라인은 **단 14분 만에 80m 규모의 3D 카트라이더 맵을 완성**시키는 압도적 생산성을 실증했습니다.
2. **에셋 배치 자동화의 맹점과 컴포넌트의 중요성**:
   * 정적 메시를 단순히 좌표 기반으로 나열하는 것은 곡선 주로에서 틈새(Gap)와 물리 걸림 문제를 유발합니다.
   * 언리얼의 고유 엔진 컴포넌트인 `SplineMeshComponent`의 정밀한 시작/끝 탄젠트 보간을 MCP 프로퍼티 주입으로 제어해야만 진정한 주행 가능(Drive-testable) 품질을 달성할 수 있습니다.
3. **인간 기획과 AI 제어의 완벽한 상호보완**:
   * "다리, 급커브, 언덕"이라는 게임의 본질적 재미와 연출 규칙은 인간 기획자(함석신, 김민주)가 정의하고,
   * AI는 복잡한 엔진 내부 C++ 리버스 엔지니어링, 포트 디버깅, 수백 개 에셋의 트랜스폼 연산과 실시간 배치 노동을 전담함으로써 2일 스프린트 목표를 20분 이상 조기 달성하는 이상적인 페어 개발 모델을 완성했습니다.
